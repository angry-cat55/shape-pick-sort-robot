## 1. 목적·일정·우선순위
사용자가 직접 학습한 CNN을 물리 시뮬레이션과 로봇 제어에 연결하고, 입력·출력·정보 경계·실패 대응을 설명할 수 있게 한다.
개인 연습 프로젝트이며 공모전 탐색·팀 프로젝트와 분리한다.
개발 시작 2026-10-04, 발표 2026-10-10 11:00 KST. 평일 수업 09:30~16:30, 과제 약 30분 후 프로젝트에 4시간 이상 가능하다는 사용자 설명.
시간은 보장된 총량이 아니며 물리 집기 실패 시 범위를 조정한다.
핵심 흐름과 ROS2 연동 > 설명 가능한 실험 근거 > 추가 UI·실험 확장. 최신 사용자 지시로 ROS2는 필수 범위다. 접촉 기반 성공 판정은 축소 대상이 아니다.

검증된 위치·치수·질량·색 범위만 생성한다. 상세 범위는 파지/관측 실험 후 설정 파일에 기록한다.

## 4. 구조·정보 경계
첫 통합은 같은 프로세스의 모듈 호출. ROS2는 초반 최소 통신 확인 후 핵심 흐름을 연결하는 필수 단계다.
- Simulation: 장면/시간/물리·카메라·관절 적용. stepSimulation을 소유하는 실행 루프는 하나.
- Perception: RGB-D만 받아 영역·CNN·기하 계산. 실제 물체 pose/class/size/body ID mask 접근 금지.
- Planning/control: 추정 중심/yaw/높이/폭→TCP 목표/IK/그리퍼·이동 순서.
- Verifier: 실제 상태·접촉으로 들림/낙하/상자 도착·추정 오차 검증. 실제 pose를 planning에 전달하지 않음.
- Task manager: 예측 클래스→상자 선택, 단계/시도/실패 분류·복구.
- Command/logging: 터미널 요청, 관측·예측·실제·판정·설정 기록.

명령→스폰→안정화→RGB-D→마스크/crop→CNN+기하→파지→실제 동작→검증→운반/재관찰→놓기→도착 검증.

### 최소 인터페이스 의미
| 데이터 | 필수 의미 |
|---|---|
| Observation | RGB, depth buffer, 카메라 view/projection·near/far, frame/timestamp |
| PerceptionResult | 관측 ID, class/score, 월드 중심/yaw/윗면 높이/관측 폭, valid/실패 이유 |
| GraspPlan | 관측 ID, 접근·파지·들림 목표, 그리퍼 개구/힘/속도 |
| VerificationResult | 작업/시도 ID, lift/drop/arrival 결과, 실패 이유, 실제 측정 |
| TaskStatus | 작업 ID, 현재 단계, 시도 횟수, 종료 이유 |
schema와 함수 signature는 실제 환경 확인 후 첫 구현 계획에 고정한다.
score는 보정된 확률을 보장하지 않는다. invalid/오래된 관측은 동작 입력으로 사용하지 않는다.
oracle 제어는 개발 실험으로 분리하며 카메라 기반 결과·성공률과 섞지 않는다.

## 5. 첫 접촉 파지 검증 절차
목적: AI/카메라 없이 고정 직육면체를 실제 접촉으로 들어 올릴 수 있는지 검증.
제품 구현 전 실제 Ubuntu/Python/PyBullet/모델/GUI 환경을 조사한다.
후보 물체 40×30×40 mm, 0.05 kg. 제안값이며 적합성 미검증.
실제 설치본 getJointInfo로 관절·손가락·링크/TCP를 확인하고 인덱스를 추측으로 고정하지 않는다.
접근·내려가기·닫기·10 cm 들기·유지·내려놓기·열기.
실행 중 resetJointState/resetBasePositionAndOrientation으로 성공 만들기 금지. 초기 reset은 구분.
물체에 createConstraint로 부착하는 최종 집기 금지.
초기 lift 판정: 물체 바닥이 테이블보다 0.05 m 이상 올라간 상태를 시뮬레이션 시간 1.0 s 유지.
목표 높이/임계값은 실험 시작값이고 변경 이유·설정 버전을 기록한다.
접촉은 보조 증거. 실제 바닥 높이 계산은 정해진 물체 geometry/pose에 따라 검증기에서 계산한다.

통과 조건:
- 고정 설정 정상 실험 10회에서 10회 lift/유지/놓기 성공. 이는 테스트 목표이며 현재 결과가 아님.
- 빗나간 접근에서 false-positive lift=0.
- 들림 뒤 개방에서 실제 낙하 및 drop 감지.
- 테이블/다른 링크가 받치는 상태를 성공으로 오인하지 않는 대조.
한 설정 통과는 다양한 물체·위치에 대한 안정성을 의미하지 않는다.
첫 약 4시간 세션 내 미통과 시 원인/TCP/충돌/힘/마찰/속도 다음 실험을 정리하고 대량 데이터 수집 보류.

## 6. 카메라·인식
빈 테이블 depth와 현재 depth 차이로 ROI의 물체 영역을 추출한다.
학습/실행 동일 crop 경로. 정답 segmentation은 인식 입력으로 사용하지 않는다.
로봇은 관찰 중 시야 밖 대기. 물체 안정화는 속도/지속 시간과 timeout으로 판정한다.
depth buffer→축방향 깊이 변환, view/projection 역투영→월드. ROS optical/OpenGL 축 차이를 기록.
실제 물체 pose는 추정 오차 평가에만 사용한다.
직육면체의 관측 중심·윗면 높이·평면 짧은 폭·yaw, 수직 원기둥의 중심·높이·지름 추정.
정방형·대칭 yaw의 모호성은 파지에 동등한 방향으로 처리한다. 보이지 않는 형상 복원 주장 금지.
영역 없음/복수 영역/NaN/범위 밖/그리퍼 초과/도달 불가를 valid=False로 처리한다.

## 7. 데이터·CNN
클래스별 300 독립 장면으로 시작. 충분성은 평가로 판단.
scene_id/seed 단위 70/15/15 분리, 같은 장면 파생 프레임은 같은 split.
클래스 공통 색 분포, 카메라/renderer/preprocess 일치, 설정·라벨·분할 저장.
64×64 RGB, Conv–ReLU–Pool 3블록과 분류층으로 시작. 채널/optimizer/LR/epoch는 학습 단계 계획에서 고정.
기본·학습률 변경·색 증강 변경 최대 3개 의미 있는 비교. 한 요인씩 변경.
validation으로 모델 선택, 최종 test는 선택 후 평가. test로 반복 튜닝 금지.
가중치+구조 식별+입력 크기/채널+정규화+클래스 순서+버전 기록.
로컬 eval+gradient 비활성화, 동일 이미지 출력을 코랩과 비교.
온라인 학습·실패 시 모델 자동 갱신 없음.

## 8. 작업·실패 대응
IDLE→OBSERVE→PLAN→APPROACH→DESCEND→CLOSE→VERIFY_LIFT→TRANSPORT→PLACE→VERIFY_ARRIVAL→DONE.
실패→RECOVER→REOBSERVE 또는 FAILED.
최초 시도+최대2회 재시도. 매 재시도 관찰을 새로 수행.
접촉 부족: 재관찰·정렬. 미끄러짐: 검증된 힘 조정·속도 감소.
도달 가능한 테이블 안 낙하만 재시도. 영역 밖/도달 불가/치수 초과/횟수 초과는 실패.
중복 시작/스폰은 작업 중 거부, 정지는 신규 동작을 멈추고 현재 물체를 불필요하게 해제하지 않는다.
최종 정지/취소 방식·힘/시간 임계값은 제어 단계 실험으로 고정하고 기록한다.
상자 도착은 실제 위치가 내부 허용 영역에 있고 안정화됐는지 검사. 예측 상자 도착과 정답 상자 도착을 별도 기록.

## 9. ROS2 필수 연동
Ubuntu 실제 배포판·Python과 호환되는 별도 workspace.
simulation bridge/perception/task manager 세 노드, 터미널 client.
영상/인식/상태 Topic, 스폰·시작·정지는 빠른 Service. 응답은 접수 의미.
긴 모션은 비동기 상태로 실행하며 callback 블로킹 금지.
Topic type/QoS/frame_id·time·관측 동기화·실행 주기는 통합 명세에서 확정.
최신 사용자 지시에 따라 최소 ROS2 연동은 필수다. 일정이 부족하면 UI·물체 변동 범위·추가 모델 비교를 줄이고, 달성하지 못한 기능은 미완료로 기록한다.

## 실험 CSV 기록 규칙
- experiment_kind로 실험 역할, pose_source로 oracle/camera를 구분한다.
- attempt_index는 최초=0, 재시도=1/2. 작업 단위와 시도 단위 분모를 구분한다.
- 미측정·해당 없음은 빈칸과 notes로 기록하며 실패0으로 해석하지 않는다.
- config_ref에 재현 가능한 설정, artifact_ref에 로그·영상 경로를 남긴다.
- recorded_at_kst는 KST offset을 포함하며 sim_duration_s와 wall_duration_s를 구분한다.
