# 프로젝트 의사결정 기록

## 다른 컨텍스트의 AI를 위한 작성 기준

이 문서는 사용자와 AI가 프로젝트를 진행하면서 결정한 사항, 검토한 다른 후보, 선택 이유를 기록한다. 발표 준비와 이후 대화 인계에 사용한다.

- 사용자는 CNN·OpenCV·ROS2 기본 개념을 수업에서 접했지만, PyBullet과 로봇암 제어는 처음 배우는 단계다. 수업 기록에 있는 내용을 능숙하게 구현할 수 있다고 가정하지 않는다.
- 선택 이유는 사용자가 발표에서 직접 말할 수 있도록 **짧게, 사용자 말투에 가깝게, 쉬운 표현과 1인칭**으로 작성한다. 아래 기록을 말투 예시로 삼는다.
- 어려운 용어가 필요하면 뜻을 짧게 풀어 쓴다. 사용자가 말하지 않은 경험·동기·숙련도를 만들어 넣지 않는다.
- 일반 의사결정은 **선택·다른 후보·짧은 1인칭 이유**로 간단히 쓴다. 구현 함수·수식·실험 로그를 매 항목에 붙이지 않는다. 자세한 로직 설명은 사용자가 요청한 항목에만 쓴다.
- 사용자가 요청한 학습용 과정 설명에서는 계산과 로직을 생략하지 않는다. 단계별 목적·입력·계산·출력을 쉬운 말로 설명하고, 필요한 수식은 기호의 뜻과 숫자 예시를 함께 적는다. 발표용 선택 이유는 짧게 유지한다.
- 계산 과정에는 실제 구현 함수와 호출하는 NumPy·PyBullet 등의 함수 이름도 함께 적어 설명과 코드를 연결한다.
- 확정된 결정과 제안·미검증 내용을 구분한다. 선택했다고 구현이나 성능 검증까지 끝난 것은 아니다.
- 새 결정은 날짜, 선택한 방식, 다른 후보, 선택 이유를 함께 기록한다. 결정이 바뀌면 이전 이유를 지우지 않고 변경 기록을 남긴다.
- 사용자의 최신 지시를 우선한다. 이 파일의 내용이 다르면 현재 상태를 확인하고 갱신한다.

## 2026-10-04 — 로봇 집기 방식

**선택:** 물체의 위치·방향·폭을 계산해 잡을 자세를 정하고, 역기구학으로 관절 목표를 구하는 방식. 역기구학은 손끝을 원하는 위치와 방향으로 보내기 위한 관절 각도 계산이다.

**다른 후보:** 강화학습으로 로봇이 잡는 행동을 배우게 하는 방식.

**선택 이유 — 발표용:**

> 아직 가상 로봇도 다뤄본 적이 없고, 프로젝트 기간도 짧아서 강화학습까지 넣으면 너무 커질 것 같았다. 먼저 물체 위치에 맞춰 로봇을 움직이고, 제대로 잡았는지 확인하는 흐름부터 이해하고 싶어서 역기구학을 선택했다. 이번에는 배운 CNN과 ROS2를 실제로 연결하는 데 집중하고, 강화학습은 기본 동작이 완성된 뒤에 도전해보려고 한다.

**범위:** CNN은 도형 종류를 학습한다. 집기는 기하 계산·관절 제어·실패 확인·재시도로 구성하며, 역기구학 계산만으로 끝내지 않는다. 강화학습은 첫 버전에서 제외한다.

**검증 상태:** 집기 방식의 선택 이유를 기록한 단계다. 실제 접촉 집기와 성공률은 아직 검증하지 않았다.

## 2026-10-04 — Panda 로봇 모델과 URDF 사용

**선택·설명:** PyBullet에 포함된 Panda 모델을 사용한다. Panda는 Franka의 로봇팔이며, 이 프로젝트에서는 두 손가락 그리퍼가 달린 가상 모델을 불러온다. URDF는 로봇의 생김새, 각 부분의 연결, 관절, 질량 등을 설명하는 파일이다.

**다른 후보:** 다른 로봇 모델을 가져오거나 직접 모델을 만드는 방식.

**선택 이유 — 발표용:**

> PyBullet에 준비된 로봇팔과 그리퍼 모델이 있어서 Panda를 선택했다. 모델을 직접 만드는 시간을 줄이고, 먼저 물체를 집는 동작을 구현하고 이해하는 데 집중하려고 한다. 이번 프로젝트에서는 ROS2로 로봇 명령을 보내고 상태와 결과를 받는 통신 흐름을 파악하는 것이 목표라서, 실무 프로젝트의 두산 M0609와 같은 모델을 찾기보다 대중적인 Panda 모델로 기본 흐름을 익히기로 했다.

**사용 방법:** 프로젝트 가상환경에서 `.venv/bin/python -m pip install -r requirements-sim.txt`로 PyBullet을 설치하면 `pybullet_data`도 함께 설치된다. 데이터는 `.venv/lib/python3.12/site-packages/pybullet_data/`에 있으므로 URDF를 프로젝트에 따로 복사할 필요가 없다. `pybullet_data`를 import해 데이터 경로를 등록한 뒤 Panda의 URDF를 불러온다.

```python
import pybullet as p
import pybullet_data

# p.connect(...)로 시뮬레이터에 연결한 뒤 실행한다.
p.setAdditionalSearchPath(pybullet_data.getDataPath())
robot = p.loadURDF("franka_panda/panda.urdf", useFixedBase=True)
```

**검증 상태:** 첫 장면에서 Panda 모델을 불러오고 대기 자세를 유지하는 것까지 확인했다. 실제 접촉 집기는 아직 검증하지 않았다.

## 2026-10-04 — 마찰계수 다양화는 후속 후보로 보류

**선택:** 현재 단계에서는 물체와 손가락의 마찰계수를 고정한다. 마찰계수 다양화는 기본 흐름을 완성한 뒤 검토할 후보로 남긴다.

**다른 후보:** 물체마다 마찰계수를 다르게 설정하고, 미끄러짐을 보고 잡는 힘을 조절하는 기능을 지금 추가하는 방식.

**선택 이유 — 발표용:**

> 아직 PyBullet과 로봇 제어를 처음 배우는 단계라, 마찰까지 바꾸고 잡는 힘을 조절하는 건 지금은 시기상조 같았다. 먼저 카메라로 물체 위치를 찾고, CNN 분류와 ROS2를 연결해서 전체 흐름을 완성하려고 한다. 마찰계수 다양화는 기본 동작이 완성된 뒤에 도전할 후보로 남겼다.

**현재 구현·한계:** 접촉 검증 코드는 마찰계수 1.0, 손가락 모터 최대 힘 20N을 사용한다. 물체의 상대 위치 변화와 접촉으로 미끄러짐·낙하를 확인하지만, 마찰계수를 추정하거나 잡는 힘을 자동 조절하지는 않는다. 마찰 다양화의 성능은 아직 검증하지 않았다.

## 2026-10-04 — 카메라 방향과 학습 입력

**선택:** 사용자 선호에 따라 카메라를 대각선 위에 둔다. 개발 검증에서 50도·65도·수직 90도를 비교한 뒤, 상면과 옆면이 함께 보이는 50도를 현재 기본값으로 설정했다. 촬영 설정과 RGB crop 처리를 데이터 수집·추론에서 공유한다.

**다른 후보:** 물체 바로 위의 수직 카메라, 촬영과 실행에서 다른 카메라 위치를 사용하는 방식.

**선택 이유 — 발표용:**

> 대각선 위에서 보면 물체의 여러 면이 보여서 도형을 구분하는 데 도움이 될 것 같았다. 학습할 때와 실행할 때 보이는 모습도 같아야 하니까 같은 카메라 위치와 이미지 처리 방식을 쓰기로 했다. 깊이는 로봇이 잡을 위치를 계산하는 데 쓰고, CNN에는 RGB 이미지를 넣으려고 한다.

**검증 상태:** 50도 카메라 좌표로 같은 직육면체 운반10/10, 두 위치·회전 변경 각1회 성공. 65도·90도도 각1회 운반 성공했다. 50도가 CNN 분류에서 더 좋은지는 아직 미검증이다. 앞의 로봇 모델·집기 방식 항목의 미검증 문장은 결정 당시 상태이며, 최신 실행 결과는 README·PROGRESS를 따른다.

## 2026-10-04 — 좌표 탐지 및 중심 계산 후 파지 결정 과정

**선택:** RGB-D 카메라에서 물체가 보이는 부분을 찾고, 깊이와 카메라 설정으로 표면의 3D 위치를 계산한다. 윗면의 가운데·높이·폭·방향으로 잡을 자세를 정하고, 역기구학과 모터 제어로 움직인다.

**다른 후보:** 시뮬레이터의 정답 위치를 직접 사용하기, RGB 사진의 가운데만 사용하기, 보이는 모든 표면을 평균 내기, 잡는 자세까지 AI로 학습하기.

**선택 이유 — 발표용:**

> 카메라로 찾은 물체를 로봇이 집는 흐름을 직접 이해하고 싶어서 깊이 정보로 위치를 계산하기로 했다. 대각선에서는 옆면도 보이니까 윗면에서 가운데와 방향을 찾는다. 계산한 가운데로 내려가고 물체 방향에 맞춰 손가락을 정렬한 뒤, 실제로 들렸는지 확인하는 방식이다.

아래는 현재 코드의 계산 순서다. 각 단계에서 무엇을 입력받고, 왜 계산하며, 결과를 어디에 쓰는지 설명한다. 수식은 미터 단위를 기본으로 한다. 예시 숫자는 이해를 위한 값이며 특정 실험 결과를 그대로 옮긴 것은 아니다.

```text
RGB·깊이 촬영 → 깊이를 거리로 변환 / 픽셀을 3D 위치로 변환
→ 깊이 차이·관찰 범위로 물체 영역 선택
→ 윗면 선택 → 긴 방향 계산 → 가운데·폭 계산
→ 입력 검사 → 손끝 목표 결정 → 역기구학·모터 이동
→ 실제 집기·낙하·도착 확인
```

### 1. 촬영: 무엇을 알고 시작하는가?

**구현 함수:** 카메라 설정은 `scripts/rgbd_camera.py`의 `camera_for_angle()`, 촬영은 같은 파일의 `capture()`에서 한다. `capture()`는 PyBullet의 `computeViewMatrix()`로 V, `computeProjectionMatrixFOV()`로 P를 만들고 `getCameraImage()`로 RGB·깊이를 얻는다. 빈 장면 촬영은 `Probe.setup()`, 물체가 있는 장면 촬영은 `Probe.observe()`에서 호출한다.

물체가 없는 테이블을 먼저 촬영한다. 이후 물체를 생성하고 1초 기다린 뒤 같은 카메라로 촬영한다. 두 영상에서 같은 픽셀의 깊이를 비교하기 위해 카메라 설정과 배경 배치를 유지한다.

현재 카메라는 관찰 중심 `(0.5, 0, 0.30)m`을 거리 1m에서 대각선 위 50도로 내려다본다. 해상도는 640×480, 시야각은 50도다. GUI에서 사람이 보는 화면의 시점을 바꿔도 이 촬영 설정은 바뀌지 않는다.

촬영 결과는 RGB, 깊이 버퍼, view 행렬, projection 행렬이다. 깊이 버퍼는 픽셀마다 저장된 0~1 숫자다. 시뮬레이터가 제공하는 물체 ID 마스크는 인식에 사용하지 않는다.

**알고 있는 값:** 카메라 위치·방향·촬영 설정, 테이블 높이, 물체를 관찰할 영역.
**찾아야 하는 값:** 물체 표면 위치, 윗면 높이, XY 가운데, 잡을 폭, 회전 방향.

이 단계는 NeRF 모델을 학습하거나 실행하지 않는다. 카메라 설정과 이미 제공된 깊이로 좌표를 계산한다.

### 2. 깊이 버퍼를 미터 거리로 바꾸기

**구현 함수:** `scripts/rgbd_camera.py`의 `depth_metres(buffer, camera)`가 아래 수식을 직접 계산한다. 별도의 학습 모델이나 거리 변환 라이브러리 함수가 아니다. `estimate()`에서 빈 영상과 현재 영상에 각각 호출한 뒤 차이를 구한다.

**목적:** 두 영상의 깊이가 '몇 mm 달라졌는가'를 비교하기 위해 단위를 맞춘다. 깊이 버퍼의 0.95는 0.95m라는 뜻이 아니다.

```text
D = n × f / [f − (f − n) × d]
```

| 기호 | 뜻 | 현재 설정 |
|---|---|---|
| d | 픽셀에 저장된 원본 깊이 버퍼 | 0~1 |
| n | 카메라의 가까운 촬영 한계(near) | 0.05m |
| f | 카메라의 먼 촬영 한계(far) | 2.0m |
| D | 변환한 깊이 | 미터 단위 |

예를 들어 `d=0.95`이면 `D=0.05×2 / [2−1.95×0.95] ≈ 0.678m`다. 이 깊이는 카메라가 보는 앞쪽 방향을 기준으로 한 거리이며, 카메라에서 표면까지의 비스듬한 직선거리와는 다를 수 있다.

이 미터 깊이는 빈 테이블 영상과 현재 영상의 차이를 계산하는 데 사용한다. 다음 단계의 3D 좌표 계산은 원본 깊이 버퍼와 카메라 행렬을 직접 사용한다. 원본 버퍼에 미터 깊이를 덮어쓰지 않는다.

### 3. 픽셀과 깊이를 가상 세계의 3D 좌표로 바꾸기

**구현 함수:** `scripts/rgbd_camera.py`의 `world_points(observation)`가 정규화부터 최종 3D 좌표까지 계산한다. `np.indices()`로 각 픽셀의 u·v를 만들고, `np.stack()`으로 네 숫자를 묶으며, `np.linalg.inv()`로 역행렬을 구한다. 행렬곱은 NumPy의 `@` 연산자, 마지막 나눗셈은 배열의 `/` 연산으로 처리한다. 아래 세 소단계 모두 이 함수 안에 있다.

**목적:** 사진의 `(u, v)`는 화면 안의 위치다. 로봇에는 가상 세계의 `(x, y, z)` 미터 위치가 필요하다. 이 공통 기준의 위치를 '월드 좌표'라고 부른다.

#### 3-1. 픽셀과 깊이의 숫자 범위를 맞춘다

현재 영상은 가로 W=640, 세로 H=480이다. u는 가로 픽셀 번호, v는 세로 픽셀 번호, d는 그 픽셀의 깊이 버퍼다. 이를 카메라 계산에 사용하는 -1~1 범위로 바꾼다.

```text
xₙ = 2u / W − 1
 yₙ = 1 − 2(v + 1) / H
zₙ = 2d − 1
```

가로는 왼쪽이 -1에 가깝고 가운데가 0에 가깝다. 세로는 이미지의 아래 방향과 계산 좌표의 위 방향이 반대이므로 뒤집는다. 코드의 `v+1`은 설치된 TinyRenderer의 픽셀·행 뒤집기 규약을 맞춘 것이다. 알려진 테이블 높이로 이 규약을 검사했다.

예를 들어 `u=320, v=239, d=0.95`이면 `(xₙ, yₙ, zₙ)=(0, 0, 0.9)`다. **범위만 바꾼 값이므로 아직 미터 위치는 아니다.**

#### 3-2. view와 projection은 각각 무엇을 하는가?

3D 장면을 사진으로 그릴 때는 다음 순서로 바꾼다.

```text
가상 세계의 위치
→ view(V): 카메라를 기준으로 한 위치로 바꿈
→ projection(P): 카메라 시야에 맞춰 화면에 그릴 좌표로 바꿈
→ 나눗셈: 최종 화면 좌표를 얻음
```

view는 카메라의 위치와 바라보는 방향을 반영한다. projection은 시야각, 화면 가로·세로 비율, 가까운/먼 촬영 한계를 반영한다. PyBullet이 이 설정으로 두 행렬을 만든다.

행렬은 여기서 '좌표의 기준과 표현을 바꾸는 계산표'라고 이해하면 된다. 예를 들어 카메라 기준 오른쪽이 가상 세계에서 어느 방향인지를 반영해 숫자를 바꾼다.

P와 V를 직접 곱하면 두 변환을 한 번에 적용할 수 있다. **`P×V`는 오른쪽의 V부터 적용하고, 그 결과에 P를 적용한다는 뜻**이다.

#### 3-3. 원래 위치를 찾으려면 계산을 거꾸로 한다

원래 위치에서 화면으로 가는 계산이 `P×V`라면, 반대 방향으로 돌아가는 계산은 그 역행렬인 `(P×V)⁻¹`이다. 역행렬은 '앞에서 했던 변환을 되돌리는 계산표'다.

```text
q = (P × V)⁻¹ × [xₙ, yₙ, zₙ, 1]ᵀ
```

`ᵀ`는 네 숫자를 세로로 놓은 벡터라는 표시다. 뒤에 1을 붙여 네 숫자로 표현하면, 좌표의 회전뿐 아니라 위치 이동과 투영도 같은 4×4 행렬 형식으로 계산할 수 있다. 코드에서는 여러 픽셀을 한 번에 처리한다.

계산 결과 q는 `(qₓ, qᵧ, q_z, q_w)` 네 숫자다. 마지막 성분으로 앞의 세 숫자를 나눠 최종 좌표를 얻는다.

```text
x = qₓ / q_w
 y = qᵧ / q_w
z = q_z / q_w
```

마지막 숫자 `q_w`는 좌표 표현의 배율이다. 예를 들어 설명용 결과가 `(1, 0, 0.68, 2)`라면 최종 위치는 `(0.50, 0, 0.34)m`다. 네 숫자 표현의 배율을 제거해 실제 세 좌표를 얻는 과정이다.

PyBullet은 행렬 숫자 16개를 열 순서로 반환하므로 코드의 `reshape(..., order="F")`로 4×4 표를 복원한다. NumPy 코드에는 픽셀들을 가로 행으로 저장해 `ndc @ inverse.T`라고 쓰는데, 이는 위의 세로 벡터 수식과 같은 계산이다.

**출력:** 각 픽셀에 보이는 표면의 `(x, y, z)` 점. 이 계산을 '역투영'이라고 부른다. 카메라에 가려진 뒷면이나 물체 내부까지 알아내는 과정은 아니다.

### 4. 깊이 차이와 관찰 범위로 물체 영역 고르기

**구현 함수:** `scripts/rgbd_camera.py`의 `estimate()`가 깊이 차이와 ROI 조건을 비교해 마스크를 만든다. `np.isfinite()`·`np.any()`로 잘못된 깊이를 검사하고, `components(mask)`로 연결된 픽셀을 묶는다. `components()`는 `np.argwhere()`로 후보 위치를 얻고 `deque` 큐로 상하좌우 이웃을 직접 방문한다.

**목적:** 앞 단계는 모든 픽셀의 표면 위치를 계산했다. 그중 물체에 해당하는 점만 남겨야 한다.

먼저 같은 픽셀에서 빈 테이블과 현재 영상의 미터 깊이를 비교한다.

```text
깊이 차이 = 빈 테이블의 D − 현재 영상의 D
깊이 차이 > 0.005m이면 물체 후보
```

예를 들어 빈 테이블 깊이가 1.00m, 현재 깊이가 0.97m라면 차이는 3cm다. 카메라에 더 가까운 표면이 생긴 후보로 본다. 차이가 5mm 이하인 곳은 제외한다.

후보 중 아래 조건을 만족하는 점만 남긴다.

- x가 0.44~0.56m, y가 -0.065~0.065m 안에 있다. 이것이 물체를 관찰할 ROI(관심 영역)다.
- z가 테이블 높이 0.30m보다 8mm 이상 높다. 테이블 가까이의 작은 차이는 제외한다.
- 깊이 버퍼가 1보다 작다. 먼 촬영 한계의 배경은 제외한다.

이 조건들의 결과가 물체 마스크다. 마스크는 '이 픽셀을 사용할지' 표시한 참/거짓 배열이며, 수업의 임계값·ROI·마스크와 연결된다.

그다음 상하좌우로 이어진 픽셀들을 한 덩어리로 묶는다. 30픽셀 미만의 덩어리는 제외하고, 남은 덩어리가 정확히 하나일 때만 진행한다. 없으면 `no_object`, 둘 이상이면 `multiple_objects`로 중단한다. 서로 붙어 하나의 덩어리로 보이는 여러 물체까지 구분하는 검출기는 아니다.

그 전에 영상 크기가 설정과 맞는지, 현재·기준 깊이에 NaN/무한대가 없는지, 현재 깊이 값이 0~1인지도 검사한다. 이 검사에서 실패하면 좌표를 계산해 로봇에 전달하지 않는다.

### 5. 윗면 고르기: 95백분위와 ±2mm를 쓰는 이유

**구현 함수:** `estimate()` 안의 `np.percentile(surface[:, 2], 95)`가 대표 높이를 구한다. `np.abs(surface[:, 2] - top_z) <= 0.002`로 높이 차이를 검사해 윗면 점만 선택한다. 별도의 윗면 탐지 모델은 사용하지 않는다.

**목적:** 대각선에서는 윗면과 카메라 쪽 옆면이 보인다. 옆면 점까지 평균 내면 한쪽으로 중심이 치우칠 수 있으므로, 현재는 평평한 직육면체의 윗면에서 가운데를 찾는다.

설명용으로 윗면 점들의 평균 x가 0.50m, 보이는 옆면 점들의 평균 x가 0.52m이고 두 그룹의 점 개수가 같다면, 전체 평균은 0.51m다. 한쪽 옆면을 많이 본 것이 중앙 위치를 바꾼 것이다.

물체 후보의 높이 z를 작은 순서대로 정렬하고 **95백분위 값**을 구한다. 100개라면 대략 95번째 근처의 높이다. NumPy는 필요한 경우 두 값 사이를 보간한다. '점의 95%를 평균 낸다'는 뜻은 아니다.

윗면이 충분히 보이는 평평한 상자라면 높은 쪽에 윗면 점들이 많이 모인다. 그래서 높은 쪽의 대표값을 윗면 높이로 사용한다. 가장 높은 점 하나보다 소수의 극단적인 높은 값에 덜 영향을 받는다. 이것은 현재 장면에 맞춘 방법이며 모든 도형에서 윗면을 보장하지 않는다.

```text
윗면 높이 z_top = 물체 후보 z값의 95백분위
윗면 후보 조건 = |각 점의 z − z_top| ≤ 0.002m
```

예를 들어 `z_top=0.34m`이면 0.338~0.342m, 즉 33.8~34.2cm의 점을 남긴다. z=32cm인 옆면 점은 제외되고 z=34cm인 점은 남는다. 옆면 맨 윗부분도 조금 포함될 수 있다.

윗면 후보가 30개 미만이면 `insufficient_top_surface`로 중단한다. **±2mm는 윗면을 고르는 범위이며, 손끝을 얼마나 깊이 내릴지 정하는 값과는 다르다.**

### 6. PCA로 긴 방향과 yaw 구하기

**구현 함수:** `estimate()`가 호출하는 `cuboid_geometry()`에서 `np.cov(xy.T)`로 공분산을 만들고 `np.linalg.eigh()`로 주요 방향을 구한다. 가장 큰 퍼짐의 방향 벡터를 골라 `np.arctan2()`로 yaw를 계산한다. PCA를 수행하는 전용 학습 모델 대신 이 NumPy 계산을 사용한다.

**목적:** 상자가 돌아가 있어도 그 방향에 맞춰 손가락을 정렬해야 한다. 윗면의 XY 점들이 어느 방향으로 길게 퍼졌는지 찾는다.

먼저 윗면 점들의 평균 위치를 구한다. 각 점이 평균에서 x와 y 방향으로 얼마나 떨어져 있는지로 공분산 행렬 C를 만든다. 공분산은 'x가 얼마나 퍼졌는지, y가 얼마나 퍼졌는지, 두 방향이 함께 어떻게 변하는지'를 담은 2×2 계산표다.

```text
각 점 pᵢ = [xᵢ, yᵢ]ᵀ
평균 μ = 모든 pᵢ의 평균
C = Σ[(pᵢ − μ)(pᵢ − μ)ᵀ] / (N − 1)
```

N은 윗면 점 개수다. 코드의 `np.cov(xy.T)`가 이 계산을 한다. `np.linalg.eigh(C)`는 점들이 퍼진 두 주요 방향과 각 방향의 퍼짐 크기를 구한다. 가장 큰 퍼짐에 해당하는 방향(고유벡터)을 긴 방향으로 사용한다. 이것이 이 코드에서 쓰는 PCA다.

긴 방향 벡터가 `(aₓ, aᵧ)`라면:

```text
yaw = atan2(aᵧ, aₓ)
```

`atan2`는 방향 벡터가 가상 세계의 x축에서 얼마나 돌아갔는지를 각도로 구한다. 예를 들어 긴 방향이 `(약 0.866, 0.5)`라면 yaw는 약 30도다.

이 방향은 반대로 가리켜도 같은 상자의 긴 축이다. 0도와 180도는 같은 양쪽 면을 잡을 수 있으므로, 코드에서 각도를 -90~90도 범위로 정리한다. 정사각형처럼 두 방향의 길이가 비슷하면 긴 방향이 모호해질 수 있다.

여기서 평균은 방향 계산에 사용한다. **최종 XY 중심은 다음 단계의 양 끝 중간으로 계산한다.**

### 7. 방향을 맞춰 가운데·폭·높이 계산하기

**구현 함수:** `cuboid_geometry()`에서 `np.cos()`·`np.sin()`으로 회전 행렬을 만들고 `xy @ axes`로 점들의 방향을 맞춘다. 배열의 `.min(axis=0)`·`.max(axis=0)`으로 양 끝을 구하고, `(low + high) / 2`로 중앙을 계산한 뒤 `@ axes.T`로 월드 좌표로 돌린다. 폭과 높이도 같은 함수에서 계산·검사한다.

**목적:** 비스듬한 상자를 가상 세계의 x/y축으로만 둘러싸면, 실제 폭보다 큰 길이가 나올 수 있다. 상자의 긴 방향과 짧은 방향에 맞춰 재야 한다.

yaw를 θ라고 할 때 그 방향을 표현하는 회전 행렬 R을 만든다.

```text
R = [[cosθ, −sinθ],
     [sinθ,  cosθ]]

방향을 맞춘 좌표 p_local = Rᵀ × p_world
```

물체를 실제로 돌리는 것이 아니라 **점들의 숫자를 상자 방향에 맞춘 축에서 다시 표현하는 것**이다. 첫 번째 축은 긴 방향, 두 번째 축은 그에 수직인 짧은 방향이다.

각 축에서 가장 작은 값 low와 가장 큰 값 high를 찾는다.

```text
방향을 맞춘 중심 = (low + high) / 2
월드 XY 중심 = R × 방향을 맞춘 중심
잡을 폭 = 짧은 축의 high − low
물체 높이 = z_top − 테이블 높이
```

회전하지 않은 상자의 예로 x 양 끝이 0.48/0.52m, y 양 끝이 -0.015/0.015m라면:

```text
가운데 x = (0.48 + 0.52) / 2 = 0.50m
가운데 y = (−0.015 + 0.015) / 2 = 0m
짧은 폭 = 0.015 − (−0.015) = 0.03m = 3cm
높이 = 0.34 − 0.30 = 0.04m = 4cm
```

회전한 상자도 방향을 맞춘 뒤 같은 계산을 하고, 가운데를 다시 월드 좌표로 돌린다. 결과는 XY 중심·윗면 높이·물체 높이·짧은 폭·yaw다. 물체 내부의 무게중심을 구한 것은 아니다.

추정 폭이 10~65mm, 추정 높이가 15~80mm 범위인지 검사한다. 물체 점이 관찰 영역 경계 2mm 안쪽에 닿으면 일부가 잘렸을 수 있어 거부한다. 이 허용 범위 전체에서 집기가 검증됐다는 뜻은 아니다. 실제 검증 대상은 현재 40×30×40mm 직육면체다.

### 8. 계산 결과를 손끝의 파지 목표로 바꾸기

**구현 함수:** `scripts/contact_grasp_probe.py`의 `grasp_plan()`이 추정 결과로 손끝 위치·yaw·열림 목표를 만들고, `Probe.observe()`가 이를 `grasp_xy`, `grasp_z`, `opening`으로 받아 사용한다. PyBullet의 `getQuaternionFromEuler()`로 손끝 방향을 표현하고 `Probe.gripper()`에 열림 목표를 전달한다. `Probe.gripper()`는 `setJointMotorControlArray()`로 두 손가락 모터를 제어한다.

**목적:** 물체의 정보를 얻었으므로 손끝을 어디로 보내고, 얼마나 돌리고, 얼마나 벌릴지 정한다. 손끝 기준점 TCP는 Panda 모델의 `panda_grasptarget`다.

```text
손끝 목표 x, y = 추정한 XY 중심
손끝 목표 z = z_top − 0.015m
한쪽 손가락 열림 목표 = (잡을 폭 + 0.015m) / 2
손끝 방향 = 아래를 향한 자세 + 추정 yaw
```

윗면보다 15mm 아래로 내려가 손가락이 옆면을 잡게 한다. 폭에는 총 15mm 여유를 더하고 양쪽이 나눠 벌어지므로 2로 나눈다. 손끝을 물체의 긴 방향에 맞춰 돌려서 손가락 사이에는 짧은 폭이 들어가도록 한다.

**잡는 높이의 기준:** 원기둥 추가 후 계산은 `grasp_plan()`의 `geometry["top_z_m"] - CONFIG["grasp_depth_below_top_m"]`로 모았으며, 설정값은 0.015m다. `Probe.observe()`가 이 결과를 손끝 목표로 사용한다. 따라서 **추정한 윗면에서 15mm 아래로 손끝 기준점(TCP)을 보낸다.** 물체의 중심 높이를 구한 뒤 그 위에 일정 거리를 더하는 방식은 아니다. 이 목표는 TCP 위치이며 손가락의 모든 접촉점이 정확히 그 높이에 있다는 뜻은 아니다.

예를 들어 테이블이 30cm, 물체 높이가 4cm인 직육면체라면 다음과 같다.

```text
34.0cm  물체 윗면
32.5cm  손끝 목표: 윗면 34cm − 1.5cm
32.0cm  물체의 기하학적 중심 높이: 테이블 30cm + 높이의 절반 2cm
30.0cm  테이블
```

이 사례에서는 결과적으로 중심보다 5mm 위지만, 계산 기준은 계속 윗면이다. 물체 높이를 H라고 하면 `손끝 목표 − 기하학적 중심 높이 = H/2 − 15mm`다. 물체 높이가 달라지면 중심과의 차이도 바뀌므로, '항상 중심보다 5mm 위를 잡는다'고 설명하면 안 된다.

손끝 자세는 코드에서 `[π, 0, yaw]`로 정한다. 앞의 π는 아래를 향하는 자세를 만드는 회전이며, yaw는 물체 방향에 맞추는 수평 회전이다. 이 자세를 PyBullet이 사용하는 쿼터니언(회전을 표현하는 숫자 4개)으로 바꿔 전달한다.

예를 들어 중심 `(0.50, 0)m`, 윗면 0.34m, 폭 0.03m, yaw 30도라면:

| 결정할 값 | 계산 결과 |
|---|---|
| 손끝 파지 위치 | `(0.50, 0, 0.325)m`: 윗면 34cm에서 1.5cm 아래 |
| 손끝 방향 | 아래를 향하고 수평으로 30도 맞춤 |
| 각 손가락 열림 목표 | `(0.03+0.015)/2=0.0225m` |
| 닫기 명령 | 각 손가락 목표 0, 모터 힘 상한 20N |

닫기 목표가 0이어도 손가락이 물체와 충돌하면 실제로는 그 앞에서 멈춘다. 모터 힘 상한 20N과 실제 접촉 힘은 다르다. 관절 열림 목표가 실제 표면 간격과 정확히 같다고도 가정하지 않는다.

**영상으로 달라지는 값:** 중심, 윗면 높이, 폭, yaw.
**현재 고정한 값:** 잡는 깊이 15mm, 열림 여유 15mm, 힘 상한 20N. 물체 높이·마찰을 보고 최적의 깊이나 힘을 자동 계산하는 기능은 아직 없다.

### 9. 역기구학으로 관절 각도를 구하고 모터로 움직이기

**구현 함수:** 동작 순서는 `Probe.run()`·`Probe.transport()`가 정하고 각 이동은 `Probe.move()`에 맡긴다. `move()`가 PyBullet의 `calculateInverseKinematics()`를 호출하고 관절 목표를 보간한다. `Probe.hold_arm()`이 `setJointMotorControlArray()`로 모터 명령을 보내고, `Probe.step()`이 `stepSimulation()`으로 실제 물리 계산을 진행한다. `getJointState()`·`getLinkState()`로 현재 관절과 실제 손끝 상태를 확인한다.

**목적:** 손끝 목표를 실제 팔 관절 7개의 목표 각도로 바꾼다. `calculateInverseKinematics()`에 손끝 기준 링크, 목표 위치, 목표 방향을 전달한다. PyBullet이 관절 각도를 반복 계산하며, 현재 최대 반복 횟수는 500회다.

관절 목표가 모델의 허용 각도를 넘으면 중단한다. 정상 범위라면 현재 관절 각도에서 목표 각도까지 조금씩 바꿔 모터에 전달한다.

```text
t = 이동 시간의 진행 비율(0~1)
s = 3t² − 2t³
각 관절의 중간 목표 = 시작 각도 + s × (목표 각도 − 시작 각도)
```

t=0이면 시작 각도, t=1이면 목표 각도가 된다. s는 시작과 끝에서 목표 변화가 느리도록 하는 계산이다. 이 목표를 모터에 보내고 1/240초씩 물리를 진행한다. 실행 중 로봇이나 물체를 순간이동시켜 성공을 만들지 않는다.

현재 접근·집기·운반 순서는 다음과 같다.

| 단계 | 목표·명령 |
|---|---|
| 접근 | 추정 중심 위 z=0.48m로 이동, 물체 방향에 맞춤 |
| 내려가기 | 추정 중심과 계산한 파지 z로 이동 |
| 닫기 | 손가락 목표 0으로 닫고 0.8초 기다림 |
| 들어올리기 | 파지 z보다 10cm 위로 이동 |
| 집기 확인 | 1초 동안 실제 물체 상태를 검사 |
| 운반 높이 확보 | 추정 중심 위 z=0.50m로 이동 |
| 상자 이동 | 그 높이에서 지정 상자의 중심으로 이동 |
| 내려놓기 | 파지 z+상자 바닥 두께와 손바닥의 최소 여유 높이 중 높은 쪽으로 이동. 아래 원기둥 항목에 변경 이유·수식 기록 |
| 놓기·후퇴 | 손가락을 열고 위로 후퇴한 뒤 도착 확인 |

각 이동 후 0.25초 기다리고 실제 손끝 위치·방향을 목표와 비교한다. 위치 오차가 6mm 또는 방향 오차가 0.10rad(약 5.7도)를 넘으면 실패로 기록한다. 이동 중 팔의 상판·상자 충돌과 손바닥의 상자 충돌도 감시한다.

관절 각도를 보간하므로 손끝이 항상 완벽한 직선을 따라간다는 보장은 없다. 현재는 검증한 경로를 사용하며 일반적인 장애물 회피 경로 계획은 아니다. 상자는 현재 CNN 분류 없이 파란 상자를 지정한다.

### 10. 실제로 집었는지·도착했는지 확인하기

**구현 함수:** `Probe.measure()`가 `getBasePositionAndOrientation()`·`getLinkState()`로 물체와 손끝 위치를 읽고, `invertTransform()`·`multiplyTransforms()`로 손끝 기준 상대 위치를 계산한다. `getContactPoints()`로 접촉, `getAABB()`로 물체 전체 범위, `getBaseVelocity()`로 움직임을 읽는다. 들림 성공은 `Probe.verify_hold()`, 운반 낙하는 `Probe.step()`, 지정 상자 도착 성공은 `Probe.transport()`에서 판정한다.

**목적:** 계산과 명령이 끝났다는 이유만으로 성공이라고 판단하지 않는다. 실제 접촉과 물체 움직임을 별도로 검사한다. 이때에만 시뮬레이터의 실제 물체 위치와 접촉을 읽어 판정·오차 평가에 사용한다.

손끝 기준 물체 위치는 손끝의 위치·방향 변환을 거꾸로 적용해서 구한다. 팔과 함께 물체가 움직여도 손끝 기준 위치는 거의 같아야 한다. 여기서 위치가 변하면 손가락 사이에서 움직였다는 뜻이다.

```text
상대 위치 r = 손끝 기준으로 표현한 물체 위치
유지 중 변화량 = 각 시점의 |r − 유지 시작 때의 r|
최대 미끄러짐 = 유지 중 변화량의 최댓값
```

여기서 `|…|`는 두 3D 점 사이의 거리다. 물체를 들어 올린 뒤 1초 동안 매 물리 계산마다 확인한다.

- 물체 바닥이 테이블보다 5cm 이상 높아야 한다.
- 테이블·상자·손가락 외 로봇 부분에 받쳐 있으면 안 된다.
- 유지 중 최대 상대 위치 변화가 1cm 이하여야 한다.

양쪽 손가락 접촉은 보조 증거로 기록한다. 위의 조건으로 성공한 뒤에는 유지 마지막 상대 위치를 운반의 기준으로 저장한다. 운반 중 **손가락 접촉이 사라지고 상대 위치도 기준에서 1cm 넘게 바뀌면** 낙하로 기록한다. 내려놓으려고 의도적으로 손을 여는 시점에는 이 운반 감시를 해제한다.

상자 도착은 물체를 감싸는 상자(AABB)로 전체가 들어왔는지 확인한다. 벽 안쪽에서 3mm 여유를 두고, 물체 바닥이 상자 바닥 높이에서 5mm 이내이며 실제 바닥 접촉이 있어야 한다. 위쪽도 벽 높이보다 3mm 낮은 범위 안에 있어야 한다. 선속도 0.01m/s 미만, 각속도 0.01rad/s 미만인 상태가 0.5초 내내 유지돼야 한다.

현재는 실패를 판정·기록하는 단계다. 실패 후 자동 재관찰·재시도는 후속 기능이다.

### 11. 계산 결과는 어디에 저장되고 어떤 범위에서 검증됐는가?

**구현 함수:** `scripts/rgbd_camera.py`의 `rgb_crop()`이 영역을 자르고 Pillow 이미지의 `.crop()`·`.resize()`로 64×64 RGB를 만든다. `save_observation()`이 Pillow의 `Image.fromarray()`·`.save()`로 그림을, NumPy의 `np.savez_compressed()`로 원본 깊이·행렬을 저장한다. 실행 설정과 요약 JSON은 `contact_grasp_probe.py`의 `main()`에서 저장한다.

좌표 추정은 `scripts/rgbd_camera.py`의 `world_points`, `estimate`에서 한다. 손끝 목표는 `scripts/contact_grasp_probe.py`의 `observe`, 역기구학·이동은 `move`, 유지 검증은 `verify_hold`에서 한다.

현재 계산한 물체 마스크로 RGB의 물체 부분을 정사각형으로 자른다. 긴 쪽 픽셀 길이에 총 12픽셀 여유를 더하고 가운데에 맞춘 뒤 64×64로 줄인다. 이는 이후 CNN 학습·추론에 공유할 crop 처리다. 현재 파지 목표는 이 작은 RGB 이미지가 아니라 앞에서 구한 깊이 기반 기하 정보를 사용한다.

실행 폴더에 카메라 설정·코드 해시·추정값·오차·집기 결과를 저장한다. 각 시도의 RGB·깊이 그림·마스크·crop·원본 깊이와 카메라 행렬도 보관한다. 원본 깊이를 남기는 이유는 좌표 계산을 다시 확인할 수 있기 때문이다.

**이 항목의 직육면체 계산 전제:** 평평하게 놓인 직육면체 하나의 윗면이 충분히 보인다. 윗면의 XY 중앙은 무게중심이 아니다. 정사각형처럼 방향이 모호한 도형이나 가려진 윗면에는 한계가 있다. 원기둥은 아래 항목의 `cylinder_geometry()`로 따로 계산한다.

**검증 상태:** 40×30×40mm/50g 직육면체의 같은 조건 카메라 운반10/10, 두 위치·회전 변경 각1회, GUI 확인까지 완료했다. 원기둥·다양한 크기·CNN·ROS2·자동 재시도는 후속 단계다. 실제 물체 좌표는 제어 목표를 정하는 데 섞지 않는다.

**선택:** 운반 호 구간에 기본 4초를 배정한다. 약 60Hz마다 시뮬레이션에서 지난 시간으로 이동 퍼센트를 구하고, 출발·도착이 부드럽도록 보정한다. 그 퍼센트에 해당하는 호 위의 손끝 위치·방향을 계산한 뒤, 역기구학으로 관절 각도를 구해 모터에 전달한다. `carry_arc()`가 경로 좌표를, `command_tcp()`가 역기구학과 모터 명령을 담당한다.

**다른 후보:** 호 위의 좌표와 관절 각도를 이동 전에 모두 계산해 저장하기.

**내가 선택한 이유:** “손끝이 바깥쪽 호를 따라가도록, 시간에 맞춰 다음 위치를 계산하고 관절 각도로 바꾸는 흐름을 사용하기로 했다.”

4초는 호 구간의 목표 이동 시간이며, 전체 집기·운반 시간이 아니다. 실제 손끝은 목표보다 늦을 수 있어서 마지막에 도착을 별도로 확인한다.

## 2026-10-05 — 손가락 동기화와 놓기

**선택:** 두 손가락이 함께 움직이게 연결하고, 바닥 가까이 내려놓는다. 놓을 때는 낮은 고정 개방 힘을 사용한다.

**다른 후보:** 손가락을 각각 움직이기, 높은 곳에서 떨어뜨리기.

**내가 선택한 이유:** “손가락이 따로 움직이면 물체가 한쪽으로 치우쳤고, 높이 놓으면 원기둥이 굴렀다. 두 손가락을 맞춰 움직이고 가까이 내려놓는 게 안정적이었다.”

물체를 손에 붙이는 연결은 아니다. 마찰을 알아내거나 잡는 힘을 자동 조절하는 기능도 추가하지 않았다.

## 2026-10-05 — 다양한 크기·회전의 학습 데이터

**선택:** 직육면체 가로·세로와 원기둥 지름은 3~6.4cm, 높이는 3~7cm로 바꾸고 Yaw도 랜덤으로 돌려 촬영한다. 2,000개 장면을 기준으로 장면별 학습/검증/테스트를 70/15/15로 나눈다.

**다른 후보:** 기본 크기만 촬영하기, 사진을 장면 구분 없이 나누기.

**내가 선택한 이유:** “크기와 비율이 달라도 도형을 구분하게 하고 싶었다. 검증 사진도 충분히 모으고, 같은 장면이 학습과 평가에 섞이지 않게 나누기로 했다.”

6.5cm는 집게 접근 여유를 반영한 이론 폭 상한이다. 경계에서 영상 추정 오차로 거부돼 1mm 여유를 남겼다. 높이7cm의 일부 독립 운반은 확인했지만 모든 크기 조합의 집기 성공은 아직 아니다.

## 2026-10-05 — Colab 랜덤 탐색과 성능 시각화

**선택:** Colab에서 학습률·손실 설정·옵티마이저 등을 랜덤 탐색하고 검증 F1로 가장 좋은 모델을 저장한다. 정확도·손실·F1·ROC-AUC·혼동행렬·오분류 사진도 함께 남긴다.

## 2026-10-05 — 정사각형 윗면의 방향·폭 계산 수정
- **선택:** `cuboid_geometry()`에서 카메라 상면 점을 둘러싸는 사각형을 여러 방향으로 비교하고, 면적이 가장 작은 방향으로 중심·짧은 폭을 구한다.
- **다른 후보:** 기존 PCA(점들이 길게 퍼진 방향 찾기) 유지, 정사각형을 계속 보류하기.
- **이유:** 정사각형은 긴 방향이 없어서 기존 계산이 흔들렸고, 6.4cm를 최대8.7cm로 잘못 봤다. 모서리에 맞는 방향을 찾으면 정사각형도 집을 수 있어서 이 방식으로 바꿨다.
- **가림 검사:** `estimate_many(..., supported_top_m=...)`에 실행 전에 정한 지원 윗면 크기를 지정한다. 기본6×4cm/원기둥지름5cm와15% 비교는 유지한다. 생성된 개별 물체의 크기·pose를 조회해 좌표를 보정하지 않는다. 임의 크기와 모든 가림을 구별하는 기능은 아직 아니다.

## 2026-10-05 — CNN 분류를 로봇 운반에 연결
- **선택:** 깊이로 찾은 영역의 RGB를 학습 때와 똑같이 잘라 CNN에 넣는다. 예측 종류로 좌표 계산 방법과 목적지 상자를 선택한다.
- **다른 후보:** 생성할 때 정한 종류로 상자 선택하기, CNN이 좌표까지 예측하게 만들기.
- **이유:** “내가 학습한 CNN으로 도형을 구분하는 모습을 보고 싶었다. 종류는 CNN이, 집을 위치는 기존 깊이 계산이 맡게 연결하기로 했다.”
- **현재 범위:** 기본 크기의 직육면체·세워진 원기둥부터 검증한다. 점수0.8 미만은 보류하고 기존 가림 검사는 유지한다. 0.8은 시작 기준이며 실제 정답률80%를 뜻하지 않는다.

## 2026-10-05 — CNN 분류 전에 옮길 후보 순서 정하기
- **기존 방식:** 한 번 촬영할 때 탐지된 모든 영역을 CNN으로 분류하고, 그중 하나를 골라 옮겼다.
- **바꾼 방식:** 깊이로 윗면 후보 점이 많은 순서를 정하고, 앞 후보부터 하나씩 CNN 분류·집기 검사를 한다. 탈락하면 다음 후보를 확인하고, 하나가 통과하면 옮긴 뒤 다시 촬영한다.
- **선택 이유:** “어차피 하나 옮기고 다시 찍는데, 매번 전부 분류할 필요는 없다고 생각했다. 필요한 후보만 분류해서 불필요한 CNN 실행을 줄이기로 했다.”

## 2026-10-06 — 실패하면 다시 촬영하고 제한해서 재시도하기

- **선택:** 집기에 실패하면 내려놓고 복귀한 뒤 다시 촬영해 새 좌표로 시도한다. 운반 중 떨어뜨리면 이동을 멈추고 복귀한 뒤 다시 촬영한다. 추가 시도는 최대 2회로 제한하고, 대상을 다시 찾지 못하거나 충돌 같은 오류가 생기면 종료한다.
- **다른 후보:** 한 번 실패하면 바로 끝내기, 성공할 때까지 계속 시도하기.
- **선택 이유:** “한 번 실패했다고 바로 끝내기는 아쉬웠다. 실패 후에는 물체 위치가 달라질 수 있으니 다시 찍어서 확인하고 싶었다. 계속 반복하지 않게 횟수를 제한하고, 위험한 오류가 나면 멈추기로 했다.”
