# PyBullet 첫 실행

## 이번 단계의 목적

바닥·Panda 로봇·직육면체를 만들고, 물체가 중력으로 내려와 바닥에 멈추는지 확인한다. 로봇은 초기 대기 자세를 유지한다. 로봇 집기·가상 RGB-D 촬영·CNN·ROS2 연결은 다음 단계다.

## 어떻게 동작하는가

```text
PyBullet 연결
→ 중력과 시간 간격 설정
→ 바닥·로봇·물체 생성
→ 시간을 조금씩 진행
→ 물체 높이·바닥 접촉·속도 확인
→ 결과 출력·연결 해제
```

- `connect`: 물리 계산을 할 세계에 연결한다. DIRECT는 화면 없이 계산하고 GUI는 같은 세계를 창으로 보여준다.
- `loadURDF`: 준비된 로봇 설명 파일을 불러온다. URDF에는 링크·관절·형상 등의 정보가 있다.
- `createCollisionShape`: 물리적으로 부딪히는 모양을 만든다.
- `createVisualShape`: 화면에 보이는 모양과 색을 만든다. 이번에는 충돌 모양과 같은 크기로 설정한다.
- `stepSimulation`: 가상 시간을 한 단계 진행한다. 물체를 만들기만 해서는 낙하 실험이 진행되지 않는다.
- `getContactPoints`: 어떤 물체끼리 접촉했는지 읽는다.

수업에서 배운 ROS2는 나중에 이 세계의 영상·명령·상태를 노드 사이에 전달한다. 지금 프로그램은 일반 Python 실행이며 ROS2 노드는 아니다. CNN은 이후 카메라 이미지로 종류를 분류한다.

## 환경과 설치

확인 환경: Ubuntu 24.04.5 / Python 3.12.3 / PyBullet 3.2.7. 프로젝트 전용 `.venv` 사용.

프로젝트 루트에서 최초 설치:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-sim.txt
```

현재 컴퓨터에는 이미 설치했다. 같은 환경을 다시 만들 때 사용하는 명령이다. 이번 설치에서는 Python 3.12용 사전 빌드 패키지가 없어 소스를 빌드했다. 컴파일러와 Python 개발 헤더는 기존 설치본을 사용했다. 시스템 Python·GPU 드라이버는 변경하지 않았다.

## 직접 실행

```bash
cd /home/dbwlghks321/shape-pick-sort-robot
```

화면 없이 물리 계산 확인:

```bash
.venv/bin/python scripts/pybullet_first_run.py --mode gui --steps 14400
```

흰 Panda와 빨간 직육면체가 바닥 위에 보인다. 빨간 물체는 시작 직후 빠르게 떨어지고, 이후 바닥에 멈춰 있다. Panda는 움직이며 집는 동작을 하지 않는다. 실행 시간이 끝나면 창이 자동 종료되며, 터미널의 Ctrl+C로 먼저 중단할 수 있다.

GUI의 시점은 장면 관찰용이다. 학습 데이터용 고정 RGB-D 카메라의 위치·방향을 확정한 것이 아니다.

가상 시간은 `steps × 1/240초`다. 480 step은 가상 시간 2초다. DIRECT는 계산을 빠르게 끝내며, GUI에서는 매 step 잠깐 쉬어 사람이 움직임을 볼 수 있게 한다. 처리·렌더링 시간이 더해지므로 실제 실행 시간은 가상 시간과 정확히 같지 않다.

## 결과 읽기

직육면체는 40×30×40 mm, 질량 0.05 kg이다. PyBullet의 길이 단위는 m이며 box 생성의 `halfExtents`에는 각 길이의 절반을 넣는다.

- 시작 중심 높이: `initial_z_m=0.2` (20cm).
- 정착 중심 높이: 약 `final_z_m=0.02` (2cm). 높이 4cm 물체의 바닥이 z=0에 놓인 상태다.
- `ground_contact_count`: 물체와 바닥 사이 접촉점 개수.
- `settled_on_ground`: 중심 높이가 0.02±0.005m이고 접촉이 있으며 선속도·각속도가 각각 0.01m/s·0.01rad/s 미만인지 확인.
- `실행 결과=`: 실제 측정값을 한글 항목명으로 출력한 행.
- `Panda 관절 수`: 설치된 모델에서 조회한 관절 개수. TCP 위치와 집기 가능성 검증은 별도다.

정상 결과는 `바닥 정착 확인: PASS`다. 너무 적은 step을 실행하면 아직 내려오는 중이므로 FAIL일 수 있다. 종료 코드는 정상 정착=0, 미정착=1, 잘못된 인자/환경=2, 중단=130이다.

## 고정 직육면체 접촉 집기

두 번째 실행 파일은 `scripts/contact_grasp_probe.py`다. 첫 실행 파일은 중력·충돌 입문용으로 보존한다.

```bash
.venv/bin/python scripts/contact_grasp_probe.py --mode gui --scenario normal
```

약 14초간 다음 과정을 보여주고 자동 종료한다.

```text
물체 안정화
→ 물체 위로 접근
→ 내려가기
→ 손가락 닫기
→ 10cm 들기
→ 1초 유지·검증
→ 원래 위치로 내려놓기
→ 손가락 열기
→ 로봇 후퇴·놓기 결과 확인
```

이번에 새로 배우는 것은 손끝 기준 좌표, 역기구학, 관절 모터 제어다.

- 손끝 기준 링크(TCP 후보): 설치된 Panda의 `panda_grasptarget`. 모델에서 손 기준 링크보다 로컬 z축으로 0.105m 떨어져 있다. 관절·링크 이름을 조회해 선택하며, 인덱스를 추측해 사용하지 않는다. 이 고정 실험의 기준점으로 검증했고 실제 로봇의 TCP 보정을 대신하지 않는다.
- 역기구학(IK): 손끝을 원하는 위치·방향으로 보내기 위한 관절 각도를 계산한다. 손끝은 아래를 향하게 설정한다.
- 관절 모터 제어: 계산한 관절 각도로 조금씩 이동한다. 초기 배치 이후 로봇·물체를 순간이동시키지 않는다.
- 그리퍼: 양쪽 손가락의 목표 위치와 힘을 지정한다. 물체는 접촉·마찰로 들리며 강제 부착 제약은 사용하지 않는다.

이 단계는 CNN 학습 없이 고정 좌표로 진행하는 **oracle 실험**이다. `oracle`은 정답 위치를 알고 있는 개발 실험이라는 뜻이다. 최종 카메라 추정 기반 파지는 이후에 연결한다. 검증기에서 읽는 물체 실제 위치는 현재 실험의 결과 확인용이다.

실험 설정은 상판 높이 0.30m, 물체 40×30×40mm/50g, 손끝 파지 목표 z=0.325m, 들기 거리 0.10m, 손가락당 모터 힘 상한 20N, 물체·손가락 마찰계수 1.0이다. 모터 힘 상한과 실제 접촉 힘은 같지 않으므로 실제 힘을 로그에 별도로 남긴다.

**성공 판정:** 물체 최저 높이가 상판보다 5cm 이상 높은 상태를 1초 유지하고, 다른 물체나 손가락 외 로봇 링크에 받쳐 있지 않으며 손끝과의 상대 위치 변화가 1cm 이내인지 확인한다. 양쪽 손가락 접촉은 보조 증거다. 내려놓기는 원래 위치 근처 상판 접촉·높이·속도를 확인한다. 상자 도착 검증은 다음 단계다.

들림 검증 이후에는 손끝과 물체의 상대 위치가 1cm 넘게 달라지고 손가락 접촉이 사라지면 낙하로 기록한다. 정상 내려놓기 후 의도적으로 여는 동작은 감시에서 제외한다. 개방 낙하 대조군은 손끝 이탈과 실제 높이 감소를 함께 확인한다.

실패 대조군을 포함한 반복 실행:

```bash
.venv/bin/python scripts/contact_grasp_probe.py --scenario all --trials 10
```

`all`은 정상 집기 10회와 다음 대조군 각 1회를 실행한다.

| 시나리오 | 실제로 만드는 상황 | 기대 결과 |
|---|---|---|
| `normal` | 가운데 정렬해 집고 내려놓음 | lift=True, place=True |
| `miss` | 목표를 옆으로 12cm 빗나가게 함 | lift=False |
| `open` | 들어 올려 검증한 뒤 그리퍼를 열음 | lift=True, drop=True |
| `support` | 높은 받침대 위에 물체를 둠 | 높이는 높아도 lift=False |

예상된 실패를 제대로 판정한 대조군도 실험 전체로는 통과다. `expectation_met`는 예상과 맞았다는 뜻이고 `lift_success`와 구분한다. 받침대 대조군의 높은 초기 배치는 실험 장면 설정이며, 정상 집기 성공을 대신하지 않는다.

매 실행 결과는 `outputs/contact-grasp/<run_id>/`에 저장된다. `config.json`은 설정·실행 코드 해시, `summary.json`은 실험별 결과, `<scenario>_<번호>.jsonl`은 20Hz 상태 기록이다. 판정은 매 물리 step(240Hz)에서 확인한다. 로그에는 단계, 물체·손끝 위치, 상대 위치, 접촉·힘, 관절 오차가 포함된다.

2026-10-04 고정 조건 정상 10회에서 들기·1초 유지·원위치 놓기 10회 모두 통과했다. 빗나감·개방 낙하·받침대 지지 대조군도 예상대로 판정했다. GUI에서도 사용자가 들고 내려놓는 모습을 확인했다. 같은 초기 조건을 반복한 결과이며, 위치·크기·회전 변화나 원기둥·운반·카메라 기반 파지의 성공률은 아니다.

## 상자 운반·도착 검증

같은 `contact_grasp_probe.py`에 운반 동작을 추가했다. 새 실행 파일 없이 시나리오를 선택한다.

```bash
.venv/bin/python scripts/contact_grasp_probe.py --mode gui --scenario transport
```

약 18초 동안 집기→들림 검증→높이 확보→파란 상자 운반→내려놓기→개방→후퇴→도착 검증을 보여준다. 상자는 바닥과 네 벽의 실제 충돌 형상으로 만들었다. 파란 상자는 중심xy=(0.35,0.25)m, 초록 상자는 (0.35,-0.25)m이다. 내부는16×16cm, 바닥 두께1cm, 벽 높이6cm다. 이번 검증의 지정 목적지는 파란 상자이며 분류 모델의 선택 결과는 아직 아니다.

**이전 집기와 달라진 점:** 손끝을 상자 벽보다 충분히 높인 z=0.50m에서 옆으로 이동한다. 상자 바닥이 상판보다1cm 높으므로 내려놓는 목표 높이도1cm 올린다. 역기구학은 각 목표의 관절 각도를 계산하고, 모터는 그 각도로 천천히 이동한다. 일반적인 장애물 회피 경로 계획을 구현한 것은 아니며 이 고정 경로에서 팔과 상판·상자 충돌을 감시한다.

도착은 중심점만 보지 않고 물체 전체 AABB(물체를 감싸는 축 정렬 상자)를 검사한다. 가로·세로는 벽 안쪽에서3mm 여유를 둔 범위, 위쪽은 벽 높이 안에 있어야 한다. 상자 바닥 높이와 접촉, 낮은 선속도·각속도가0.5초 유지돼야 통과한다. 들고 상자 위에 있는 상태나 벽에 걸친 상태를 도착으로 처리하지 않는다.

```bash
.venv/bin/python scripts/contact_grasp_probe.py --scenario all_transport --trials 10
```

| 시나리오 | 검증하는 상황 | 기대 판정 |
|---|---|---|
| `transport` | 집어 파란 상자에 놓기 | 집기·지정 목적지 도착 성공, 낙하 없음 |
| `transport_drop` | 운반 중간에 그리퍼 열기 | 낙하 감지, 도착 실패 |
| `wrong_bin` | 초록 상자로 운반하기 | 물리적 놓기는 성공, 지정 목적지 도착은 실패 |

`all_transport`는 정상 운반을 지정 횟수만큼 반복하고 대조군을 각각1회 실행한다. 기존 `all`은 원위치 집기 대조군 묶음이다. 두 그룹 모두 예상된 실패를 올바르게 구분하면 실험 통과다.

운반 결과의 `commanded_bin_arrival`은 명령한 상자에 도착했는지, `arrival_success`는 지정된 파란 상자에 낙하 없이 도착했는지다. 초록 상자를 의도적으로 선택한 대조군은 전자가True, 후자가False다. 이것을 CNN 분류 정확도로 해석하지 않는다.

위 내용은 고정 좌표 실험이다. 아래 단계에서 카메라 추정을 연결했다. CNN·ROS2·자동 재시도와 다양한 크기의 성능은 아직 미검증이다.

## RGB-D 영상으로 좌표를 찾아 집기

이번에는 `scripts/rgbd_camera.py`가 영상에서 좌표를 계산하고, 기존 `contact_grasp_probe.py`가 그 결과로 로봇을 움직인다. 새 Python 파일 하나는 카메라 역할, 새 테스트 하나는 좌표 계산 검증 역할이다.

```text
물체 없는 테이블의 깊이 촬영
→ 물체 생성·안정화 → 같은 카메라로 RGB·깊이 촬영
→ 깊이 차이와 관찰 영역으로 물체 픽셀 선택
→ 픽셀·깊이를 월드 좌표로 변환
→ 직육면체의 상면에서 중심·높이·폭·회전 추정
→ 추정값으로 손끝 목표 계산 → 기존 집기·운반 → 실제 접촉·도착 검증
```

수업에서 배운 마스크·ROI는 관심 픽셀을 선택하는 부분과 연결된다. 새로 배우는 역투영은 카메라의 위치·방향과 투영 행렬을 이용해 영상의 픽셀을 가상 세계의 미터 좌표로 바꾸는 계산이다. 깊이는 카메라와 보이는 표면 사이의 거리 정보를 준다. 보이지 않는 면을 복원하는 학습은 하지 않는다.

옆면까지 모두 평균 내면 중심이 카메라 쪽으로 치우칠 수 있다. 현재는 평평한 직육면체 하나의 높은 상면만 선택하고 PCA(점들이 길게 늘어선 방향을 구하는 계산)로 방향과 짧은 폭을 구한다. 파지 높이는 추정 상면보다 15mm 낮게 정한다. 이 깊이는 현재 40mm 높이 물체에서 검증한 값이며 임의 크기에 대한 보장은 아니다.

**촬영 설정:** 물체 관찰 중심 `(0.5, 0, 0.30)m`, 거리 1m, 수평 기준 내려다보는 각도 50도, 640×480 RGB-D, FOV 50도, near/far 0.05/2.0m, TinyRenderer. XY 관찰 영역은 `x=0.44~0.56m`, `y=-0.065~0.065m`다. GUI에서 마우스로 화면 시점을 바꿔도 이 촬영 설정은 바뀌지 않는다. 로봇은 영상 왼쪽에 보이지만 물체 관찰 영역을 가리지 않는 대기 자세를 쓴다.

50도·65도·수직 90도에서 각 한 번 운반을 확인했다. 50도는 상면·옆면이 함께 보여 기본값으로 사용한다. 이것이 CNN 분류 정확도 면에서 가장 좋다는 검증은 아직 없다. 데이터 수집과 추론은 같은 설정·64×64 RGB crop 경로를 사용할 예정이다. 깊이는 좌표 계산용이고 CNN의 입력은 RGB다.

```bash

.venv/bin/python scripts/contact_grasp_probe.py --mode gui --pose-source camera --scenario transport

# 동일 조건 10회와 운반 낙하·다른 상자 대조군을 검사한다.

# 위치와 회전을 바꾸고 추정값으로 집는다. yaw는 라디안 단위다.
```

## 원기둥 계산과 크기 변경의 상세 기록

아래는 의사결정 문서에서 옮긴 구현 설명과 당시 실험 기록이다. 현재 기본값은 앞의 크기 확대 항목을 따른다.

## 2026-10-04 — 도형별 기하 계산과 원기둥 집기·놓기

**선택:** 촬영·깊이 처리·윗면 선택은 공통으로 사용하고, 직육면체와 원기둥의 가운데·폭·방향 계산만 함수로 나눈다. 계산 결과를 같은 형식으로 전달해 집기·운반·검증은 재사용한다.

**다른 후보:** 모든 도형을 직육면체의 PCA 방식으로 처리하기, 원기둥 전용 실행 프로그램을 새로 만들기, 원 테두리를 정교하게 맞추는 계산을 처음부터 추가하기.

**선택 이유 — 발표용:**

> 원기둥은 윗면이 원이라 직육면체처럼 긴 방향을 찾을 필요가 없었다. 그래서 도형에 따라 가운데와 폭을 구하는 함수만 나누고, 계산한 위치로 움직이고 집혔는지 확인하는 부분은 같이 쓰기로 했다. 나중에 다른 도형을 넣을 때도 필요한 계산을 추가할 수 있게 했다.

### 1. 공통 처리 뒤에 도형별 함수를 선택한다

`estimate(..., object_shape)`가 위 항목의 촬영 이후 깊이 검사·역투영·물체 마스크·95백분위/±2mm 윗면 선택을 공통으로 처리한다. 그 뒤 윗면 점의 XY 좌표를 `cuboid_geometry(xy)` 또는 `cylinder_geometry(xy)`에 전달한다. 이 두 함수는 `scripts/rgbd_camera.py`에 있다.

직육면체는 PCA로 긴 방향과 짧은 폭을 구한다. 원기둥은 원형 윗면의 X·Y 양 끝으로 가운데와 지름을 구한다. Python 도형 클래스를 새로 만드는 대신 필요한 함수 두 개로 나눴다.

현재 종류는 `--object-shape cuboid/cylinder` 명령으로 지정한다. 생성할 때 쓴 지름·높이·위치는 인식 함수나 파지 함수에 넘기지 않는다. 종류 입력은 이후 CNN 예측 결과로 바꿀 수 있지만 현재 분류 성능을 검증한 것은 아니다.

### 2. 원기둥의 중심과 지름을 계산한다

**구현 함수:** `cylinder_geometry(xy)`에서 배열의 `.min(axis=0)`·`.max(axis=0)`으로 윗면 점의 양 끝을 구한다. `.mean()`으로 X·Y 지름을 평균 낸다.

```text
중심 x = (윗면 점의 최소 x + 최대 x) / 2
중심 y = (윗면 점의 최소 y + 최대 y) / 2
X 방향 지름 Dₓ = 최대 x − 최소 x
Y 방향 지름 Dᵧ = 최대 y − 최소 y
잡을 폭 D = (Dₓ + Dᵧ) / 2
```

예를 들어 x가 48.5~51.5cm, y가 -1.5~1.5cm라면 중앙은 (50cm, 0cm), 두 방향의 지름은 각각3cm여서 잡을 폭도3cm다.

수직 원기둥의 원형 윗면은 어느 수평 방향으로 재도 지름이 비슷하다. X·Y 지름 차이가 평균 지름의20%를 넘으면 `non_circular_top`으로 거부한다. 이는 잘림·잘못된 상면 등의 일부 사례를 거부하는 검사이며, 도형 종류를 분류하거나 모든 기울기를 판별하는 기능은 아니다.

원기둥에는 고유한 긴 방향이 없으므로 yaw=0으로 고정한다. 따라서 물체의 초기 수평 회전각을 그대로 따라 돌리지 않는다. **수직으로 서 있고 전체 윗면이 충분히 보이는 원기둥**을 전제로 한다. 가려진 원의 중심을 추정하는 정교한 원 맞춤 계산은 아직 없다.

### 3. 같은 형식의 결과로 손끝 목표를 만든다

**구현 함수:** `estimate()`는 두 도형 모두 `center_xy_m`, `top_z_m`, `height_m`, `width_m`, `yaw_rad`를 반환한다. `scripts/contact_grasp_probe.py`의 `grasp_plan(geometry)`가 이 값으로 파지 목표를 만든다.

```text
파지 위치 = [중심 x, 중심 y, 윗면 z − 15mm]
한쪽 손가락 열림 목표 = (잡을 폭 + 15mm) / 2
수평 방향 = 직육면체는 추정 yaw / 원기둥은0
```

`Probe.observe()`는 이 계획을 받아 손끝 방향을 아래로 설정하고 `Probe.gripper()`로 미리 연다. 이후 `Probe.run()`·`Probe.move()`·`Probe.verify_hold()`·`Probe.transport()`가 기존 이동·접촉 검증을 수행한다.

**파지 높이는 계속 윗면 기준15mm 아래**다. 물체 중심 높이를 기준으로 바꾸지 않았다. 원기둥 높이3cm와5cm에서도 이 파지 깊이를 검사했다. 이것이 모든 높이의 최적 깊이라는 뜻은 아니다.

### 4. 낮은 원기둥을 놓을 때 손바닥·상자 벽 충돌을 피한다

처음에는 상자에 내려놓을 높이를 `파지 z + 상자 바닥 두께`로 정했다. 높이3cm 원기둥을 이렇게 내리자, 손바닥이 높이6cm 상자 벽에 걸려 목표보다 위에 멈췄다. 실제 재현에서 `panda_hand` 링크와 상자 벽의 접촉을 확인했다. 초기 실패 로그는 `outputs/cylinder-validation/20261004T221654/small_left/`에 보존했다.

**구현 함수:** `Probe.transport()`에서 아래 계산으로 놓을 높이를 정한다. `Probe.measure()`는 `getContactPoints()`로 팔뿐 아니라 손바닥의 상자 충돌도 감시한다.

```text
명목 놓기 높이 = 파지 z + 상자 바닥 두께(10mm)
최소 놓기 높이 = 상자 바닥의 윗면 z + 손바닥 여유(25mm)
실제 놓기 목표 = max(명목 놓기 높이, 최소 놓기 높이)
```

상자 바닥 윗면이31cm, 작은 원기둥의 파지 높이가31.5cm인 설명용 예시라면 명목 놓기 높이는32.5cm, 최소 높이는33.5cm다. 높은 쪽인33.5cm에서 의도적으로 손을 연다. 물체는 남은 짧은 거리를 중력으로 내려가 바닥에 정착한다.

이25mm는 현재 Panda 손바닥·상자 벽 배치에서 검증한 값이다. 어떤 로봇과 상자에도 그대로 맞는 값은 아니다. 놓기 전에 손을 여는 높이를 보완한 것이며, 물체를 잡을 때의 깊이15mm나 집기 성공 기준을 완화하지 않았다.

놓는 시점에는 의도적 해제이므로 운반 중 낙하 감시를 해제한다. **도착 성공은 여전히 물체 전체가 상자 안에 있고 실제 바닥 접촉·낮은 속도가0.5초 유지될 때만 판정**한다. 손을 열었다는 이유만으로 성공 처리하지 않는다.

## 2026-10-04 — 기본 도형을 더 크게 표시하기

**선택:** 직육면체는6×4×6cm, 원기둥은 지름5cm·높이6cm로 키운다. 작은 크기 유지, 카메라만 확대, 로봇 자체 확대도 후보였지만 실제 물체가 작다는 요청에 맞춰 물체 크기를 바꿨다. Panda 집게의 최대 벌림은 약8cm이고 접근 여유도 필요하므로 잡는 폭은 각각4cm·5cm로 정했다.

`CONFIG["block_size_m"]`는 직육면체 생성 크기, `--cylinder-diameter/--cylinder-height`는 원기둥 생성 크기다. `Probe.setup()`에서 반길이 또는 반지름으로 변환해 PyBullet 충돌·표시 형상을 만든다. 생성 크기는 카메라 추정과 `grasp_plan()`에 전달하지 않는다. 고정 정답 실험의 TCP만 새 상면36cm−1.5cm=34.5cm로 바꿨다.

높이6cm 물체 전체가 들어가도록 상자 벽도6cm에서8cm로 높였다. 기존 성공 기준은 물체 윗부분이 벽 위보다3mm 아래여야 하므로, 물체만 키우면 상자가 너무 낮다. 벽이2cm 높아진 만큼 손바닥 충돌을 피하는 놓기 최소 TCP 높이도 바닥+25mm에서+45mm로 높였다. 놓기 목표는 여전히 `max(파지 높이+바닥 두께, 바닥 높이+45mm)`다. 집는 깊이15mm와 도착 판정은 완화하지 않았다.

**도착 검증:** `Probe.measure()`가 `p.getAABB()`로 물체 전체의 XY 범위와 높이를 읽는다. 전체 XY가 상자 안쪽3mm 여유 안에 있고, 물체 바닥과 상자 바닥 높이 차이가5mm 미만이며, 윗부분도 벽보다3mm 아래인지 확인한다. `p.getContactPoints()`로 실제 바닥 접촉을 확인하고 `p.getBaseVelocity()`로 이동·회전 속도가 각각0.01m/s·0.01rad/s 미만인지 확인한다. `Probe.transport()`에서 이 상태가0.5초 유지되어야 도착으로 판정한다. 카메라 좌표는 제어 입력이고, 이 정답 조회는 검증용이다.

**실제 결과:** `outputs/larger-defaults-validation/20261004T223806/`에서 두 종류 각각 기본 위치10/10 성공·낙하0/10. 각 종류 XY=(0.48,-0.025), yaw=-0.35와 XY=(0.52,0.025), yaw=0.6도 각각1회 성공. 운반 낙하·다른 상자 대조군 판정 통과, 전체 테스트19개 통과. 질량50g·마찰1.0·힘 상한20N은 유지했으며 밀도나 실제 재질에 맞춘 질량 증가를 검증한 것은 아니다. CNN 학습 데이터는 이 변경된 설정으로 앞으로 생성한다.

## 2026-10-05 — 하나씩 운반하고 다시 촬영하기

```bash
.venv/bin/python scripts/multi_object_scene.py --mode gui --task sort --cuboids 5 --cylinders 0 --seed 0
.venv/bin/python scripts/multi_object_scene.py --mode gui --task sort --cuboids 0 --cylinders 5 --seed 0
```

GUI는 작업 종료 시 닫힌다. `--mode direct`로 화면 없이 실행할 수 있다. 기본 `--task scene`은 장면 확인만 한다. CNN 전이므로 `sort`에서는 한 종류만 선택한다.

동작 흐름은 다음과 같다.

1. `estimate_many()`가 깊이 차이로 물체 영역을 나누고 기존 `estimate()`로 각 윗면의 중심·폭·방향을 계산한다.
2. 지원하는 기본 크기와 윗면 크기가 15% 넘게 다르면 보류한다. 윗면 점 부족·구역 경계·비정상 깊이도 거부한다. 모든 가림을 판별하는 기능은 아니다.
3. `sort_scene()`은 윗면 점이 많이 보이는 대상 하나를 선택하고 `grasp_plan()`으로 손끝 목표를 만든다. 종류는 수동 입력이며 CNN 예측이 아니다.
4. `SceneProbe.move()`가 작은 손끝 이동 구간마다 IK를 계산한다. 여러 팔 자세 중 목표 방향을 향하는 대기 자세에 가까운 쪽을 선호해 과하게 접히는 경우를 줄인다.
   운반 호는 `SceneProbe.carry_arc()`로 이어서 움직인다. 중간 각도마다 멈추지 않고 시작과 끝에서만 감속하며, 약60회/초 IK 목표를 갱신한다. 몸통을 피하는 경로와 충돌·낙하 감시는 유지하고, 호 끝과 집기·놓기 지점의 위치 확인은 남긴다.
5. 실제로 집고 들림을 확인한 뒤, 높은 경유점으로 로봇 바깥쪽을 돌아 뒤 상자의 빈 자리로 간다. 상자 변에 맞춰 손끝 방향을 바꾸고 바닥 가까이 내려놓는다.
6. 손가락끼리의 기어 연결은 두 손가락의 움직임을 맞추기 위한 것이다. 물체를 붙이지 않는다. 집는 모터 힘 상한은 20N이며, 놓을 때만 고정된 0.1N 개방 상한을 쓴다. 마찰 추정·힘 자동 계산은 하지 않는다.
7. 최대 5초 안에 물체 전체의 상자 내부 포함·실제 바닥 접촉·낮은 속도가 0.5초 연속 유지되어야 도착으로 판정한다. 다른 상자 도착은 `wrong_bin_arrival`로 구분한다.
8. `return_to_wait()`가 모터로 대기 자세에 돌아온 뒤 다시 촬영한다. 안 보이는 물체가 남았으면 완료 대신 `no_valid_target`으로 중단한다. 마지막에는 모든 물체의 도착을 다시 확인한다.

시뮬레이터의 물체 ID·정답 좌표는 선택한 대상의 평가와 도착 검증에만 사용한다. 파지 좌표를 정답으로 고치지 않는다. 회전 원기둥은 느슨한 PyBullet AABB 대신 실제 치수·축 방향으로 표면 경계를 계산해 검증한다.

설정은 `config.json`, 전체 결과는 `summary.json`, 단계별 제어·접촉 기록은 `sort/motion.jsonl`에 저장한다. `sort/scan_00/`부터 촬영마다 RGB·깊이·물체별 crop·mask·좌표와 보류 이유를 남긴다. 기본 출력 경로는 실행마다 새 폴더다. 직접 같은 출력 폴더를 재사용하면 예전 번호 파일 일부가 남을 수 있으므로 별도 폴더를 지정한다.

최종 운반 검증: 두 종류 각각 1·2·5개, seed0~2의 **18개 장면 / 총48개 물체 도착**. `outputs/sequential-validation/verified/results.json`과 각 장면의 원본 기록을 보존했다. 중간 실패는 `initial/`, `final/`, `outputs/sequential-debug/`에 남겼으며 최종 성공 숫자와 섞지 않는다. CSV에는 중간 CLI18개와 최종18개 장면을 따로 기록했다.

가림 대조에서는 고정판으로 물체를 가렸을 때 완료로 오인하지 않는지, 판 제거 후 재촬영에서 드러나는지 검사했다. 이 판 제거는 관측 테스트 전용이며 로봇 운반 성공 실험이 아니다. 깊이 영상에서 윗면 절반을 잘라 보류하는 검사도 포함한다. 다른 크기의 큰 물체를 자동으로 옮겨 뒤의 작은 물체를 발견하는 전체 동작은 이번 결과로 검증했다고 하지 않는다.
